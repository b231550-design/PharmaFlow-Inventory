# 1. PROBLEM STATEMENT

A neighbourhood pharmacy stocks medicines in batches, each with its own expiry date. When dispensing a medicine, the pharmacy should use the batch that expires soonest first, and never dispense an expired batch.

The pharmacist needs to:

* Manage medicines and their individual batches.
* Track stock quantities and expiry dates.
* Dispense medicine using First-Expiry-First-Out (FEFO).
* Prevent expired medicine from being dispensed.
* Calculate the actual sellable stock of a medicine, excluding expired batches.
* Search for a medicine and know whether it is currently in date.
* Receive alerts for batches that are about to expire.

The product must work for any pharmacy, not just a single hardcoded pharmacy.

# 8. CORE BUSINESS LOGIC — MOST IMPORTANT

Implement FEFO correctly.

FEFO means First-Expiry-First-Out.

When a pharmacist requests to dispense a medicine:

1. Find all batches for that medicine belonging to the authenticated pharmacy.
2. Exclude batches whose expiry date is before the current business date.
3. Exclude batches with zero available quantity.
4. Sort eligible batches by earliest expiry date ascending.
5. If expiry dates are equal, use a deterministic secondary ordering, such as createdAt ascending or batch ID ascending.
6. Allocate the requested quantity from the earliest-expiring batch first.
7. If that batch does not have enough stock, continue to the next eligible batch.
8. Stop when the requested quantity is fulfilled.
9. If total sellable stock is insufficient, reject the entire dispensing request without partially reducing stock.
10. Create a dispensing record showing exactly which batches were used.
11. Return a clear response with the allocation breakdown and remaining sellable stock.

Example:

Batch A: 50 tablets, expiry 2026-09-30.
Batch B: 100 tablets, expiry 2026-12-15.
Batch C: 75 tablets, expiry 2027-03-10.
Batch D: 40 tablets, expiry 2026-08-01.

Assume the current business date is 2026-09-17.

Sellable stock = 225 tablets.

If the pharmacist dispenses 120 tablets:

* Batch A: 50 tablets.
* Batch B: 70 tablets.
* Batch C: 0 tablets.
* Batch D: 0 tablets because it is expired.

Remaining sellable stock = 155 tablets.

The system must never dispense Batch D.

## Critical correctness requirements

Use a reliable MongoDB transaction/session strategy for stock deduction and dispensing record creation. Handle concurrent dispensing requests safely.

Do not:

* Deduct stock before validating availability.
* Allow negative quantities.
* Include expired batches in sellable stock.
* Select batches based on insertion order.
* Trust a client-provided expiry status.
* Rely only on frontend validation for expiry protection.
* Create a dispensing record if stock deduction fails.
* Deduct stock without recording the transaction.

If MongoDB transactions require a replica set, document the requirement and provide a practical local development setup.
